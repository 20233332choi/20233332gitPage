0. 버전 비교 (v1.1 vs v2.0)

SCSS v2.0은 기존 물리 서버 의존성과 수동 엑셀 동기화 방식을 전면 개정하여, Docker 기반 아키텍처와 관리자 대시보드 자동화를 실현한 대규모 성능 업데이트 버전입니다.

1. 시스템 개요 및 개발 배경

1.1 개발 취지

군 복지시설(상승레스텔)의 프런트 데스크 관리와 온라인 복지포털 간의 실시간 데이터 연동이 부재하여, 기존에는 관리병이 예약 내역을 대조한 후 손님들에게 도어락 비밀번호를 수작업으로 조회하여 문자를 발송하는 비효율적인 프로세스로 운영되었습니다. 이는 업무 과부하와 비밀번호 오타 전송 등의 운영 오류를 유발했습니다.

SCSS는 예약고객이 프런트 키오스크나 모바일에서 직접 본인의 예약번호를 통해 객실 호수와 도어락 비밀번호를 실시간 조회 및 확인할 수 있는 무인 자동화 체계를 구축하여, 24시간 무인 프런트 대응을 원활하게 실현하고 행정 소요를 극적으로 단축했습니다.

[실물 가동 전경] 상승레스텔 로비 프런트 데스크에 배치되어 24시간 상시 운용 중인 SCSS 로컬 키오스크 화면

1.2 실전 투입형 애자일 개발 (Agile Development)

실전 운영 기반의 반복 수정: 본 시스템은 가상 테스트에 머무르지 않고, 개발 초기 단계의 프로토타입을 실제 군 복지시설 현업에 직접 배치하여 매일 입·퇴실하는 손님들과 시설 관리병의 실시간 피드백을 수용하며 버그 패치와 기능 개선을 반복하여 완성도를 끌어올린 "검증된 상용 솔루션"입니다.

1.3 1인 개발 비하인드 스토리 (개발자 에세이)

본 프로젝트는 개발 당시 일병이었던 최형민 개발자가 군 복무 중 복지시설의 고질적인 수동 행정 프로세스를 개선하고자 시작한 1인 자동화 프로젝트입니다. 비전공자 및 인프라의 제약이라는 벽을 극복하기 위해, 복무 중 AI 에이전트(Agent AI)를 페어 프로그래밍 파트너이자 기술 멘토로 삼아 긴밀히 조력하며 시스템의 전체 아키텍처를 구상하였습니다.

프로그램 구축에 필요한 핵심적인 기반 지식을 쌓기 위해 일과 후와 개인 정비 시간을 활용하여 파이썬(Python) 프로그래밍 언어의 기본기와 소켓 및 웹 기반의 네트워크 구조를 치열하게 독학하였습니다. 이러한 자기주도적 학습과 AI의 협업을 통해 설계된 SCSS v1.0은 실제 운용 환경에 배치된 후 수많은 실무 피드백을 거쳤으며, Docker 가상화 기술을 주입한 v2.0에 이르기까지 성공적으로 고도화되어 실질적인 국방 행정 자동화 혁신을 달성하였습니다.

2. 시스템 아키텍처

SCSS는 가볍고 효율적인 Python Flask 프레임워크와 OS 환경 격리를 위한 Docker 컨테이너 기술을 융합하여 상시 구동 안정성을 극대화했습니다.

구성 요소 핵심 기술 스택 역할 및 상세 설명
Flask Web App Flask, Waitress WSGI 사용자 체크인 요청 처리 및 도어락 비밀번호 데이터베이스 매핑/조회 API 서버 구동.
Admin Module HTML5, JavaScript, CSS3 실시간 투숙 현황 파악, 수동 체크인 기능 및 객실 비밀번호 동적 반영 대시보드.
Selenium Crawler Selenium, Chrome Headless 복지포털 사이트에 자동 로그인하여 최신 예약 데이터를 안전하게 다운로드 및 정제.
APScheduler APScheduler (cron) 매일 14:50 최신 데이터 갱신 스케줄러 실행 및 09:00 청소목록 자동 출력 트리거링.
Docker Engine Docker Compose 개별 OS 종속성 제거 및 컨테이너 내부 네트워크망 보안 격리 유지.

모든 데이터 트래픽은 보안 정책상 지정된 내부 포트 80(HTTP)을 통해 통신하며, 관리 서비스는 로컬 프런트 단말기 및 지정된 내부 인프라 단말기로 접근이 제한되어 있습니다.

3. 관리자 모듈 주요 기능

3.1 실시간 투숙 현황판 (`/admin/status`)

  • 시각화 관리: 각 객실의 상태를 색상 코드(체크인 전: 오렌지, 입실 완료: 그린, 퇴실 대기: 그레이)로 시각화하여 프런트 데스크 상황 한눈에 조망.
  • 수동 오버라이드: 연세가 많으시거나 단말기 조작이 어려운 고객이 내방 시, 관리자가 현황판에서 클릭 한 번으로 체크인을 대리 강제 처리할 수 있는 오버라이드 기능 구현.
  • 자동 로그 기록: 모든 체크인 요청 시각, 예약번호, 객실 호수는 즉시 암호화 처리 후 data/checkin_log.csv 파일에 영구 기록되어 감사 데이터로 보관.

3.2 객실 비밀번호 동적 관리 (`/admin/ppc`)

  • 난수 생성 알고리즘: 중복 및 연속된 숫자를 원천 배제한 높은 보안성의 4자리 난수 도어락 비밀번호 생성.
  • 적용 대기 상태 (Pending): 즉시 비밀번호가 변경되어 고객이 구 비밀번호로 출입을 못 하는 사고를 예방하기 위해, 난수를 미리 임시 엑셀(pending/)에 저장하고 관리병이 직접 도어락 물리 키에 비번을 입력했음을 승인(Cover)한 시점에 실서비스에 반영(Live)하는 안전 프로세스 도입.

4. 설치 및 실행 가이드 (Docker 기반)

프로젝트를 신규 인프라에 배포하거나 로컬 테스트 환경을 구축하기 위한 빌드 프로세스입니다.

4.1 환경 설정 (.env)

루트 폴더에 .env 파일을 생성하고 아래와 같이 관리자 자격증명 및 크롤링 계정을 주입합니다.

# SCSS System Environment Configuration
ADMIN_PASSWORD=change_this_to_secure_password
WELFARE_PORTAL_ID=welfare_account_id
WELFARE_PORTAL_PW=welfare_account_secure_password
PORT=80

4.2 서비스 빌드 및 실행

컨테이너 백그라운드 상주를 보장하는 구동 명령어입니다.

# 1. 원격 리포지토리로부터 코드 클론
git clone https://github.com/20233332choi/ROKA_SCSS.git
cd ROKA_SCSS

# 2. Docker compose 백그라운드 빌드 및 실행
docker-compose up -d --build

# 3. 서비스 프로세스 가동 상태 점검
docker-compose ps
배포 주의사항: 외부 인터넷망에 포트가 바로 노출되지 않도록 서버 OS 레벨의 방화벽(UFW 등)에서 내부망 고정 IP 대역 외의 접속 요청은 물리적으로 Drop 처리하십시오.

5. 원격 자동 업데이트 및 유지보수

5.1 자동 업데이트 시스템

실제 운용 환경에서는 수동 터미널 제어 없이 최신 릴리즈 패치를 안전하게 반영하기 위해 스크립트 기반의 핫 릴리즈 프로세스를 지원합니다. auto_update.bat(윈도우) 또는 auto_update.sh(리눅스) 실행 시 작동하는 파이프라인 프로세스는 다음과 같습니다.

@echo off
echo [SCSS Update Pipeline Starting...]
cd /d %~dp0
git fetch origin main
git reset --hard origin/main
docker-compose down
docker-compose up -d --build
echo [SCSS Update Successfully Finished!]
pause

8. 향후 기능 확장 및 개발 가이드

SCSS 아키텍처는 유연한 모듈화 설계를 채택하고 있어 다른 서비스와의 연동 및 확장 개발이 용이합니다.

8.1 SMS / 알림톡 발송 모듈 추가

조회 단말을 쓰지 않고도 손님에게 예약 승인 비밀번호를 자동으로 발송할 수 있도록 SMS Gateway(예: CoolSMS, Aligo 등)를 연동할 수 있는 예시 구조입니다.

# sms_gateway.py
import requests

def send_checkin_sms(phone_number, room_no, password):
    url = "https://api.sms-gateway.service/send"
    payload = {
        "to": phone_number,
        "from": "010-XXXX-XXXX", # 공인 발신 번호
        "text": f"[상승레스텔 안내] 객실: {room_no}호 / 비밀번호: {password} / 입실시간 15:00 이후"
    }
    headers = {"Authorization": "Bearer YOUR_GATEWAY_API_KEY"}
    response = requests.post(url, json=payload, headers=headers)
    return response.status_code == 200

8.2 데이터베이스(SQLite / MySQL) ORM 전환 가이드

엑셀 파일 기반의 대용량 동시 요청 트래픽 처리 한계를 개선하기 위해 SQLAlchemy ORM 기반의 스키마 매핑 예제 코드입니다.

from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class Reservation(db.Model):
    __tablename__ = 'reservations'
    id = db.Column(db.Integer, primary_key=True)
    res_no = db.Column(db.String(50), unique=True, nullable=False) # 예약번호
    name = db.Column(db.String(100), nullable=False)
    room_no = db.Column(db.String(10), nullable=False)
    in_date = db.Column(db.Date, nullable=False) # 입실일자

  • 도어락 비밀번호는 오타 전송 등의 인적 예외 방지를 위해 무조건 관리페이지(/admin/ppc) 대시보드 도구로만 수행합니다.
